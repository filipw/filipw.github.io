Warm up

Symmetric cryptography

The most popular symmetric algorithm is the Advanced Encryption Standard (AES)

AES with 256 bit key length is approved by NSA for top secret information.

RSA is considered to be partly legacy, but still it makes a good example to illustrate certain concepts - because they are applicable to the alternative algorithms as well.
Symmetric cryptography is fast and relatively simple, but requires a secure method for key distribution, which is a big challenge.
Asymmetric cryptography solves it by using a pair of keys - public and private, underpinned by mathematically hard problems.

Asymmetric cryptography

Also known as Public Key Cryptography. It is also used for digital signatures.
  • 🔒 Key exchange/establishment
    → establishing a secure communication channel
    → then hand over to symmetric encryption for efficiency
  • ✍️ Digital signatures
    → create and verify signatures
    → serve as proof of digital content authenticity and integrity
Many protocols - for example TLS/SSL - use a hybrid model - start with an asymmetric handshake, and then switch to symmetric.

Asymmetric cryptography is based on difficult mathematical problems:

  • 🧮 factorizing large composite numbers - RSA
  • 🧮 elliptic curve discrete logarithm problem - EC Cryptography

Quantum threats

In quantum theory a basic unit of information is called a

qubit

Just like a bit, qubit has only two observable (basis) states

$ \ket{0} \rightarrow $ maps to bit 0

$ \ket{1} \rightarrow $ maps to bit 1

Mathematically, a qubit state is described by a vector.
Schrödinger's cat was both dead and alive at the same time. It's NOT that he was dead or alive and Schrödinger simply did not know. Only once Schrödinger opened the box, because of "observation", would the cat's fate be decided.

Program evolution

type input execution output
Classical 01011 $\rightarrow$ 11011 $\rightarrow$ 00110
Quantum $\ket{1}\ket{0}\ket{0}\ket{0}\ket{1}$ $\rightarrow$ $\ket{\psi}$ $\rightarrow$ $\ket{0}\ket{1}\ket{0}\ket{1}\ket{0}$

The strength of quantum computers is that they are able to take algorithmic advantage of superposition. This is called

quantum parallelism

  1. Create a superposition of all possible results
  2. Use interference to amplify correct result, and cancel out bad results

source: Stefano Markidis, KTH Royal Institute of Technology, https://arxiv.org/abs/2405.07222

Heuristically, and at the risk of over-simplifying, quantum parallelism allows quantum computers to evaluate a function $f(x)$ for many different values of $x$ simultaneously.

- Nielsen and Chuang

By using Hadamard gates to create an equal superposition of all possible inputs, a single quantum circuit can compute a function $f(x)$ for every possible value at the exact same time. This single step generates a massive, combined quantum state that holds information about all input-output pairs. However, quantum parallelism alone is not enough to outperform classical computers; because measuring the state forces it to collapse into just one random input-output pair, quantum algorithms must use additional tricks to extract useful, global information from the superposition before making a measurement.

One of the most widely used public-private cryptosystems is RSA (Rivest–Shamir–Adleman)

Its security relies on the factoring problem - recovering two large primes from their product.

RSA is considered to be partly legacy, but still it makes a good example to illustrate certain concepts - because they are applicable to the alternative algorithms as well.

RSA

  • 1. Pick two huge prime numbers $p$ and $q$
  • 2. Pick public exponent $e$ (usually 65537)
  • 3. Publish public key $N = p \times q$ and $e$
  • 4. Encrypt:
    $C = M^e (mod\;N)$
  • 5. Decrypt:
    Calculate private key $d = e^{-1} \pmod{(p-1) \times (q-1)}$
    $M = C^d \pmod{N}$
The value of e is almost always fixed to 65537.

Effectively, the security of RSA boils to the fact that

finding $p$ and $q$ is impossible

if you only know $N$.

In 1994, Peter Shor developed an integer factorization algorithm for quantum computers that runs in polynomial time, achieving an exponential speed up over the fastest known classical alternative.

Factoring a number $N$

  • 1. Pick random $a < N$ that is relatively prime to $N$
  • 2. Find the period $r$ of the function $f(x) = a^x \pmod N$
  • 3. If $r$ is even, calculate candidates for $p$ and $q$:
    $\gcd(a^{\frac{r}{2}} + 1, N)$ and $\gcd(a^{\frac{r}{2}} - 1, N)$

Example: factoring 15

  • 1. Set $a = 13$
  • 2. Find order $r = 4$
  • 3. Calculate:
    $p = gcd(170, 15) = 5$
    $q = gcd(168, 15) = 3$

5 and 3 are factors of 15.

Shor's algorithm relies on inverse Quantum Fourier Transform used for function order finding. QFT is exponentially faster than any classical alternative.

Shor's algorithm is a hybrid classical-quantum method - gcd is still done classically.

Forward secrecy means using new (ephemeral) keys all the time, so intercepting and breaking one message would not reveal the whole session. ECDH is also used in tools like Signal or Skype.

Until early 2026, the best published estimate of what Shor's algorithm needs to break RSA-2048 was¹:

  • 🧮 ~1,400 logical qubits
     → ideal, error-free qubits - a mathematical abstraction, not something you can buy.
  • 🧮 897,864 physical qubits
     → 2D surface code with nearest-neighbour connectivity, 0.1% physical gate error rate, less than a week of runtime.


¹ C. Gidney, "How to factor 2048 bit RSA integers with less than a million noisy qubits," arXiv:2505.15917 (2025).

In February 2026, Iceberg Quantum's Pinnacle Architecture cut the physical overhead by an order of magnitude²:

  • 🧮 ~1,400 logical qubits
     → same algorithm and logical requirements as above - the savings come from better error correction.
  • 🧮 < 100,000 physical qubits (~94,000)
     → QLDPC (Quantum Low-Density Parity Check) codes that need non-local connectivity, 0.1% physical gate error rate, about a month of runtime (a week with ~139,000 qubits).


² P. Webster et al. (Iceberg Quantum), "The Pinnacle Architecture: Reducing the cost of breaking RSA-2048 to 100 000 physical qubits using quantum LDPC codes," arXiv:2602.11457 (2026).

March 2026: Google Quantum AI (with the Ethereum Foundation and Stanford) re-estimated the cost of breaking 256-bit elliptic curves³ - secp256k1, the same size as the P-256 behind most ECDSA/ECDH:

  • 🧮 1,200-1,450 logical qubits
     → 70-90 million Toffoli gates (RSA-2048 above: ~1,400 logical qubits, 6.5 billion Toffolis).
  • 🧮 < 500,000 physical qubits
     → superconducting, 0.1% error rate, nearest-neighbour grid; one key in 9-23 minutes - ~20x fewer qubits than the previous best estimate.
  • 🤐 attack circuits withheld
     → a zero-knowledge proof of the resource counts was published instead.


³ Google Quantum AI, Ethereum Foundation, Stanford, "Securing Elliptic Curve Cryptocurrencies against Quantum Vulnerabilities," arXiv:2603.28846 (March 2026).

Why cryptocurrencies are the canary in the coal mine:

  • ₿ ~6 million BTC already have their public key on-chain
     → ~30% of supply (Glassnode, 2026): 1.9M BTC in early P2PK outputs (incl. ~1.1M attributed to Satoshi) + 4.1M through address reuse; Taproot exposes keys by design. Harvest now, steal later.
  • ⏱️ everyone else is exposed while spending
     → the public key sits in the mempool until the transaction confirms - a 9-23 minute attack fits inside Bitcoin's ~10-minute block interval.
  • 🔧 fixing it takes a soft fork plus years of block space
     → BIP-360 (Pay-to-Merkle-Root) merged Feb 2026, not activated; BIP-361 would sunset ECDSA/Schnorr ~5 years later, leaving unmigrated coins unspendable - and moving every UTXO needs 76-568 days of blocks.
  • 🏆 state of the art: a 15-bit key
     → Project Eleven's 1 BTC Q-Day Prize (April 2026): a 15-bit curve broken on IBM hardware. Bitcoin needs 256.

Google's own recommendations in the whitepaper blog post: move blockchains to PQC, stop exposing or reusing addresses, and think about policy for abandoned coins; Google itself has a 2029 migration deadline. Also in March 2026, Cain et al. (Harvard, Caltech and collaborators) showed that neutral-atom hardware could run Shor's algorithm at cryptographic scale with⁴:

  • 🧮 as few as 10,000 reconfigurable atomic qubits
     → high-rate error-correcting codes on reconfigurable atom arrays instead of a fixed 2D grid; runtime is traded for qubit count.
  • 🧮 26,000 physical qubits → P-256 in "a few days"
     → factoring RSA-2048 takes one to two orders of magnitude longer.
  • 🔬 grounded in 2025 experiments
     → below-threshold logical operations on hundreds of atoms and arrays of more than 6,000 atoms.


⁴ M. Cain et al., "Shor's algorithm is possible with as few as 10,000 reconfigurable atomic qubits," arXiv:2603.28627 (2026).

Today's quantum hardware:
  • 🧮 up to 96 logical qubits
     → Harvard/MIT/QuEra (Nov 2025): 448 neutral atoms, with error rates that improved as the system scaled (below threshold)
  • 🧮 up to 6,100 physical qubits
     → Caltech (Sept 2025): neutral atoms trapped in a laser-driven grid - a qubit array, not yet a full computer
  • 🧮 ~100 qubits in error-corrected, gate-based machines
     → Google Willow (105), Quantinuum Helios (98 physical → 48 logical), IBM Nighthawk (120)

In 1996, Lov Grover developed a quantum search algorithm through an unsorted data set - finding $x$ for $f(x) = y$, when $y$ is known.

It provides quadratic speedup over the classical counterparts.

Because of that it can be used to attack symmetric encryption schemes such as AES, however that can be easily countered by increasing the key size.

Post quantum cryptography

In 2016 NIST (National Institute of Standards and Technology) announced a post-quantum cryptography competition, with the aim to provide a set of standardized crypto schemes resistant to quantum threats.

In July 2022 the first four algorithms to be standardized were announced.

  • 🔐 CRYSTALS-Kyber
    key encapsulation, lattice-based
  • ✍️ CRYSTALS-Dilithium
    signature, lattice-based
  • ✍️ FALCON
    signature, lattice-based
  • ✍️ SPHINCS+
    signature, hash-based
Kyber & Dilithium were selected to be primary general-purpose protocols for key encapsulation and digital signatures. FALCON was recommended for applications requiring smaller digital signatures. SPHINCS+ was chosen as a backup option to the lattice-based approaches.

$t = (\braket{\mathbf{a}, \mathbf{s}} + \varepsilon) \mod q$

  • · $\braket{\mathbf{a}, \mathbf{s}}$ is the dot (inner) product of two vectors
  • · $\varepsilon$ is the error term, chosen from a specific distribution
  • · $q$ is the modulus, confining the value to a predictable range
  • · $t$, $q$, and $\mathbf{a}$ are published, but $\mathbf{s}$ and $\varepsilon$ are kept secret

note: this is a simplified picture of LWE, for illustrative purposes only

The security in LWE comes from the fact that, while it is straightforward to compute $t$ given $\mathbf{a}$, $\mathbf{s}$, $q$, and $\varepsilon$, it is computationally hard to reverse this process. The difficulty arises from the addition of the error term $\varepsilon$, which obscures the relationship between $t$ and $\mathbf{s}$, making it infeasible to recover $\mathbf{s}$ given $t$, $\mathbf{a}$, and $q$.

The first PQC standards were finalized in August 2024 - more are in the pipeline.

  • 🔐 ML-KEM (Kyber)
    → Module-Lattice-Based Key-Encapsulation Mechanism
    → FIPS-203
    → standardized in 2024
  • 🔐 HQC
    → Code-Based KEM - a non-lattice backup for ML-KEM
    → FIPS-207 (expected)
    → selected in March 2025; draft still pending, final expected 2027
  • ✍️ ML-DSA (Dilithium)
    → Module-Lattice-Based Digital Signature Standard
    → FIPS-204
    → standardized in 2024
  • ✍️ SLH-DSA (SPHINCS+)
    → Stateless Hash-Based Digital Signature Standard
    → FIPS-205
    → standardized in 2024
  • ✍️ FN-DSA (Falcon)
    → FFT over NTRU-Lattice-Based Digital Signature Standard
    → FIPS-206

NIST's transition timeline (IR 8547, Nov 2024 - still a draft)

  • ⚠️ 2030: 112-bit security deprecated
    → e.g. RSA-2048, ECDSA/ECDH with P-224
  • ⛔ 2035: all RSA and ECC disallowed
    → every non-quantum-resistant public-key algorithm is out
  • ⚡ 2026: the US made 2030 binding
    → EO 14412 (June 2026): PQ key exchange on federal high-value systems by end of 2030, PQ signatures by end of 2031

It is no longer only NIST - governments are setting their own deadlines

  • 🇪🇺 EU Coordinated Implementation Roadmap (June 2025)
    → end of 2026: national PQC strategies and first steps
    → end of 2030: high-risk use cases and critical infrastructure migrated
    → end of 2035: everything else, as far as feasible
  • 🇬🇧 UK NCSC migration timeline (March 2025)
    → 2028: discovery and migration plan
    → 2031: highest-priority migrations complete
    → 2035: migration complete
  • 🇺🇸 US Executive Order 14412 + OMB M-26-15 (June 2026)
    → end of 2030: PQ key establishment on federal high-value systems
    → end of 2031: PQ authentication (signatures)
    → 2035: full migration; national security systems follow NSA CNSA 2.0 (2030-2033)
  • 🇦🇺 Australia ASD Information Security Manual
    → end of 2030: stop using RSA, DH, ECDH and ECDSA altogether
    → the most aggressive public timeline so far

There are plenty of issues with the current timeline

  • 🚨 Too Slow for Confidentiality
    → sensitive data vulnerable to "Harvest Now, Decrypt Later" attacks
  • ⚖️ Signatures ≠ KEMs
    → encryption needs urgent migration; digital signatures can safely transition later
  • 🔗 Thin Guidance on Hybrid
    → SP 800-227 (2025) blesses KEM combiners; nothing yet for hybrid signatures
  • ⚙️ Embedded HW Lifecycle
    → automotive and IoT sectors struggle with 2035 due to long hardware lifetime

IETF standardization is moving from drafts to RFCs:

  • 🤝 RFC 10024 (August 2026)
    → Hybrid key exchange for TLS 1.3: X25519MLKEM768, SecP256r1MLKEM768, SecP384r1MLKEM1024 (formerly draft-ietf-tls-ecdhe-mlkem).
    → Standards Track - the default in all major browsers, OpenSSL 3.5+, Apple platforms 26 and (opt-in) Windows Schannel.
  • 🚀 draft-ietf-tls-mlkem
    → Pure post-quantum key exchange for TLS 1.3.
    → IESG-approved in 2026 (Informational), RFC number pending; not yet widely supported.
  • 🛠️ draft-ietf-tls-mldsa
    → ML-DSA for authentication (certificates) - together with ML-KEM this gives pure PQC TLS.
    → In IESG review since mid-2026.
  • 🌳 draft-ietf-plants-merkle-tree-certs
    → Merkle Tree Certificates: shrink post-quantum authentication for the WebPKI.
    → Chrome + Cloudflare live experiment since early 2026; Let's Encrypt targets production in 2027.

Post-quantum key exchange is already mainstream (2026):

  • 🌐 Web / TLS
    → Chrome, Edge, Firefox and Safari (iOS/macOS 26) default to X25519MLKEM768
    → about two-thirds of human HTTPS traffic to Cloudflare is PQ-protected, but only ~9% of origin servers support it
  • 🔑 SSH
    → OpenSSH 10.0+ (April 2025) defaults to mlkem768x25519-sha256
  • 💬 Messaging
    → Signal: PQXDH (2023) + SPQR "triple ratchet" (October 2025)
    → Apple iMessage PQ3 (2024)
  • 🧰 Platforms and runtimes
    → OpenSSL 3.5 (2025), Windows CNG (Nov 2025) + Schannel (July 2026), Apple CryptoKit (2025)
    → Java 24, Go 1.24 and .NET 10 (2025)

Cryptography in .NET

  • 🧩 Official system API surface
    → System.Security.Cryptography namespace across all platforms
  • ⚙️ Native backends per OS
    → Windows: CNG / CAPI
    → Linux: OpenSSL
    → macOS/iOS: CryptoKit+CommonCrypto
    → Android: JCA / OS crypto
  • 🌐 Third-party implementations
    → Portable across platforms (e.g. BouncyCastle)
    → Can implement algorithms not in OS
    → No hardware acceleration/FIPS compliance
The .NET crypto API is unified, but the runtime delegates to the OS crypto stack for performance, compliance, and integration. This means your code looks the same, but the actual implementation varies by platform.

Open Quantum Safe maintains liboqs - an open-source C library of quantum-resistant algorithm implementations, meant for prototyping and research rather than production.

Maybe LibOQS.NET is a thin .NET wrapper around liboqs, providing easy access to post-quantum cryptography features for .NET developers. Version 0.4 (August 2026) tracks liboqs 0.16 and ships native binaries for Windows, Linux (glibc and musl) and macOS.
